# 蜂宅 CRM・報價（前端）

靜態網頁前端，資料都在 Google 試算表，透過 Apps Script 網頁應用程式 API 讀寫，需要密碼登入。
這個 repo 只有畫面程式碼，不含任何客戶資料或密碼。

## 各工程報價

案件頁以工程卡片分開顯示木作、水電等工程的項目數與小計。各工程可獨立新增、修改、列印；手機版使用逐項欄位，整案總額與整案報價單仍可查看。

沿用既有 Apps Script API 與試算表欄位，不需要重新部署後端。儲存某工程時，會重新讀取最新整案、保留其他工程，並建立整案草稿版本；已送出或已簽約的舊版本保留於「整案報價歷史」。報價狀態、版本編號及合約／工期引用仍屬於整案，並非每個工程各有一個後端報價 ID。

儲存前若發現同工程內容已變動，會停止儲存並保留編輯畫面。現有後端沒有條件式寫入／版本鎖 API，因此無法保證兩台裝置在最後讀取與寫入之間同時儲存時的原子性；多人高頻共同編輯需後續配合後端鎖定。

以 `node tests/verify-quotes.cjs` 執行虛構資料測試，涵蓋單工程編輯、其他工程合併、同名品項、衝突提示、重複送出、單工程／整案列印及儲存失敗重試。

## 載入與預覽

同一分頁保留最多 15 分鐘的近期資料，重新整理時先顯示，再背景讀取最新版。快取使用 API 網址與登入權杖的 SHA-256 識別值隔離，不另存權杖；登出、授權失效及寫入操作會清除。首次進入或新分頁仍須等候 Apps Script 後端，不代表後端執行時間已縮短。儲存空間或 Web Crypto 不可用時，回退為正常線上讀取。

背景更新不重畫已開啟的編輯表單，失敗時保留目前資料並提供重試；同步中的重複載入會共用請求。執行 `node tests/verify-loading.cjs` 驗證快取先顯示、背景同步、表單保留、登入隔離、登出清除與寫入競態。

工程編輯頁的「預覽／列印此工程」直接使用目前填寫的明細，無須先儲存或再讀取後端。預覽可開關 5% 設計監工費，總計及付款金額會同步重算；關閉時不列費用項目。此選項只影響本次預覽與列印，不改變後端儲存的整案費率／合約金額。返回編輯會保留原輸入、變更說明與費用選擇。

報價明細依不可變的報價版本 ID 共用讀取請求，保留最多 12 份近期明細於同分頁快取；重新載入案件資料不再清掉已讀明細。首頁會預載第一個案件的最新報價。編輯器只建立所選工程的單價選單，避免每次生成全部工程的品項。按鈕立即顯示開啟狀態，讀取失敗可重試，唯讀請求超過 30 秒會停止等待；寫入不自動中止或重送。

儲存仍先讀取最新整案與明細以檢查衝突，過程分別顯示確認、讀明細、寫入及案件更新進度；成功寫入後保留已確認的明細，避免重整案件後再多讀一次相同報價。Apps Script 首次讀取及實際寫入仍取決於後端回應時間。

客戶版使用 A4 室內裝修報價版型：案件名稱取自案件資料，廠商為「蜂宅室內裝修有限公司 林晉安」，不顯示訂單編號。項目、規格說明、數量、單位、單價與金額分欄；保護工程再分公共區域與室內兩組，各組獨立編號。規格輸出會移除成本、毛利、倍率及單價公式等內部資訊，保留施工與材料說明，原始內部備註不變。
